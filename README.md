# Range Marine / OK-Boats — Apify + Python market monitor

Пилот автоматического мониторинга пяти открытых источников яхтенных новостей с помощью Python, Apify Website Content Crawler и GitHub Actions.

Источники: Yamarin, Axopar, FJORD, BENETEAU и PressMare. Пилот по-прежнему загружает максимум **две страницы на источник**, но теперь также **извлекает ссылки на потенциальные статьи из уже загруженного Markdown** (не посещая эти ссылки, без дополнительных запусков Actors). Результаты: URL, заголовки, SHA-256 содержимого, время проверки, события изменения, ссылки-кандидаты и отчёты об ошибках. Полные тексты и фотографии не сохраняются. Цены, наличие, комплектация и VAT **не проверяются**.

## Настройка

1. Получите токен Apify в https://console.apify.com/.
2. Откройте этот репозиторий: Settings → Secrets and variables → Actions → New repository secret.
3. Создайте секрет `APIFY_TOKEN` (не вставляйте его в код или чат).
4. Откройте Actions → OK-Boats yacht market source monitor → Run workflow.
5. В поле **mode** выберите **recover** для повторного чтения уже завершённых Actor-запусков 4 ноября 2026 года. Этот вариант **не создаёт новые запуски Actors** и не дублирует их платную работу (при условии сохранности datasets на Apify). Для нового сбора выберите **live** — он запустит до 5 Actors и может потреблять платные ресурсы.
6. Проверьте журнал Actions и файлы в `data/`.

Расписание: каждый день в 07:23 UTC (10:23 по Стамбулу), возможны задержки GitHub Actions. В первый успешный запуск формируется базовый снимок, в следующие — события `CONTENT_CHANGED`.

В режиме live код выполняет Actor `apify/website-content-crawler`. Лимиты на источник: максимум 2 страницы и `max_total_charge_usd=0.10` для модели pay-per-event. **Это не гарантирует общий потолок расходов на вычисления/прокси**; проверьте цены и настройте бюджет/оповещения в Apify до запуска.

## Проверка локально

```bash
python -m pip install -r requirements.txt
python -m monitor.main --check-config
python -m unittest discover -s tests -v
python -m monitor.main  # требует APIFY_TOKEN в окружении
```

Модуль не изменяет OK-Boats.com, CRM и рабочий репозиторий `rangemarine`. Статус сбора не следует считать подтверждённым до успешного live-запуска в GitHub Actions.

## Первая диагностика (04.11.2026)

Первый рабочий процесс выполнил запуск Actors на Apify, но обработка полученного ответа остановилась на `AttributeError`: SDK `apify-client>=3` возвращает типизированный объект `Run`, а первоначальный код ожидал словарь. Исправлено использование `run.status`, `run.id`, `run.default_dataset_id`. Предыдущие журналы не переписываются. Для восстановления данных первого запуска используется неизменяемая карта ID в `config/first_run_ids.json`; режим `recover` не запускает Actors заново. В будущем для регулярного мониторинга используйте `live` (автоматическое расписание уже работает в этом режиме).

`runs.jsonl` сохраняет источник, тип ошибки, этап, статус Actor и идентификатор запуска, но не API-токен и не содержимое страницы. Фактическую цену ранее выполненных запусков проверяйте в Apify Console: ограничения `max_total_charge_usd` не являются универсальным лимитом расходов при pay-per-usage.

## Редакционный отбор v2 — правила и файлы

- `monitor/editorial.py`: **правила предварительной классификации по заголовку**. Категории `PREMIERE`, `PROPULSION`, `TECHNICAL_UPDATE`, `CORPORATE`, `NEEDS_REVIEW`, а для разделов навигации — исключение `SECTION_INDEX`.
- Приоритеты: `P1` для премьер и моторизаций, `P2` для технических обновлений, `P3` для корпоративных событий и `REVIEW` при недостатке сигнала. **Это не утверждённые статьи и не окончательные факты.**
- `premiere_scope` различает заявленный в заголовке американский/европейский дебют и мировую премьеру. Не переносите этот признак в статью без проверки первоисточника.
- `data/editorial_candidates.jsonl` — пополняемый реестр кандидатов с меткой `NEEDS_EDITOR_REVIEW`; `data/editorial_latest.md` — отчет последнего запуска; `data/discovered_links.jsonl` — только новые ссылки, найденные в уже загруженном Markdown (`LINK_ONLY_UNFETCHED`).
- URL с датой может дать `date_hint_from_url`, **не** подтверждённую дату публикации. `NEW_PAGE` означает первое обнаружение монитором; `CONTENT_CHANGED` может быть изменением футера, меню или HTML. Проверку фактов, SEO и медиаправ выполняет редакция отдельно.
- **Охват не исчерпывающий:** Markdown может не содержать ссылок, а часть сайтов использует динамическую загрузку, пагинацию или неполный список новостей. Лимит `max_pages=2` остаётся без изменения стоимости пилота. Увеличивать его следует только после анализа полноты и затрат Apify.

### Без дополнительных расходов Apify: классифицировать уже собранные 9 страниц

GitHub Actions → OK-Boats yacht market source monitor → Run workflow → `mode: classify` (вариант по умолчанию). Режим запускает только локальный Python, читает сохранённый `data/changes.jsonl`, не требует API-токен и **не запускает Actors**. По текущей базовой выборке ожидаются 4 отдельные статьи и 5 индексных страниц; это предварительный результат анализа уже сохранённых заголовков. `classify` не удаляет и не переписывает исходные `observations.jsonl`, `changes.jsonl` и `last_seen.json`.

Для нового сбора используйте `mode: live`, при котором Actors могут потреблять платные ресурсы. `mode: recover` повторно читает datasets первого запуска, не создавая новых Actors; этот режим не означает получение свежих новостей.

Локально: `python -m monitor.main --rebuild-editorial` и `python -m unittest discover -s tests -v`.
